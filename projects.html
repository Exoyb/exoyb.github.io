// project_002/readme

Botium Toys Security Audit

  • My first structured security audit project.
  • Reviewed Botium Toys’ assets, existing security controls and compliance practices to identify gaps and where the biggest risks sat.
  • Completed a controls and compliance checklist.
  • Produced a prioritised set of recommendations for the IT Manager, explaining why the gaps mattered and suggesting realistic ways the business could improve them.
$ cat scope.txt

What I assessed

The audit covered the organisation’s wider security programme, including employee devices, internal systems and networks, data storage, legacy systems and existing physical and technical controls.

$ cat findings.txt

What stood out

The biggest gaps included broad access to sensitive data, no encryption for cardholder information, no least privilege or separation of duties, no IDS, no backups or disaster recovery plan, and weak password controls.

$ cat response.txt

What I recommended

I prioritised the recommendations by risk and implementation effort, then suggested practical fixes around access control, encryption, permissions, backups, disaster recovery, passwords, intrusion detection, asset classification and legacy system monitoring.

// recommendations --priority

Priorities

CRITICAL

Access control and encryption. Sensitive customer and payment data needed protecting first.

HIGH

Least privilege, separation of duties, backups, disaster recovery and stronger password security.

MEDIUM

Password management, IDS, asset classification and regular legacy system monitoring.

Version history

Release notes live with the project. Cyber Log records the milestone itself.

V1.2 Performance + usability 11 SEP 2026 RELEASED
$ cat context.txt

Context

Family testing exposed two separate usability problems: moving between pages felt slower than it should, and the first power screen looked like an error instead of something the visitor was meant to interact with.

$ cat changes.log

Changes

  • Asked family to test the site and used their feedback as the starting point for the release.
  • Investigated the page-navigation path after testers reported that swapping between pages felt slow.
  • Found and removed an unnecessary 230ms JavaScript delay from internal navigation.
  • Researched browser prefetching and added low-priority prefetching for the main portfolio pages during the roughly 12-second boot sequence, using otherwise hidden boot time to warm the browser cache before navigation.
  • Standardised shared CSS and JavaScript cache-busting URLs so the browser can reuse the same cached files between pages instead of treating them as different requests.
  • Kept performance claims grounded: the improvement depends on browser, connection and cache state, so I did not claim a fixed percentage without a measured benchmark.
  • Replaced the boot-screen Audio on/off control with a [ SKIP BOOT SEQUENCE ] button and made skipping abort the remaining POST/SSH sequence cleanly.
  • Changed SYSTEM OFFLINE to PRESS TO POWER ON after family testing showed the old wording was being read as an error rather than an interactive screen.
  • Added a blinking red standby LED so the powered-off state reads more clearly.
  • Changed the power-on state so the LED turns green, flickers slowly, speeds up, then settles solid green before POST begins.
  • Matched the outer panel border flicker to the power-button state so the workstation appears to stabilise as one system.
  • Removed the redundant click/tap helper line once the new wording and LED made the interaction clear enough on their own.
$ cat outcome.txt

Outcome

  • Internal navigation no longer includes the deliberate 230ms pause.
  • The boot window can now be used to prefetch the main destination pages and warm shared browser cache before the visitor starts navigating.
  • The first-load power state is clearer without relying on an extra instruction line.
  • Visitors who do not want the full POST/SSH sequence can skip it cleanly.

The site was still a fairly normal portfolio. I wanted it to feel more like my own project and make the cyber/security direction obvious as soon as somebody landed on it.
